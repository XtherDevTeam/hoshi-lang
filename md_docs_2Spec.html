Hoshi Language Specification

1. Introduction

Hoshi (also referred to as Yoi-lang in documentation) is a statically-typed, strongly-typed programming language. It aims to support modern programming paradigms, including Object-Oriented Programming (OOP) and Generic Programming (GP), while maintaining a clear and efficient compilation process.

The language compiles to its own high-level intermediate representation (Yoi IR) before being translated to LLVM IR for native code generation. It features a reference-counting-based memory management system for its object model.

2. Lexical Structure

2.1. Comments

Hoshi supports C-style comments:

  • Single-line comments: Start with // and continue to the end of the line.
  • Multi-line comments: Start with /* and end with */.

2.2. Keywords

The following are reserved keywords and cannot be used as identifiers:

use, func, interface, struct, impl, let, in, for, forEach, while, if, elif, else, return, continue, break, cast, null, constructor, import, export, as, from, true, false.

2.3. Identifiers

Identifiers are used for naming variables, functions, types, etc. They must start with a letter or an underscore (_) and can be followed by any number of letters, digits, or underscores.

2.4. Literals

  • Integer Literals: Sequences of digits representing 64-bit signed integers (e.g., 123, 1048576).
  • Decimal Literals: Sequences of digits with a decimal point, representing 64-bit floating-point numbers (e.g., 1919.810, 3.5).
  • Boolean Literals: true or false.
  • String Literals: A sequence of characters enclosed in double quotes ("</tt>). Object Model and Lifecycle @subsection autotoc_md38 4.1. Everything is an Object All data types in Hoshi are objects allocated on the heap. This includes primitive types like <tt>int</tt> and <tt>bool</tt>, which are wrapped in corresponding object structures (e.g., <tt>YoiIntegerObject</tt>). @subsection autotoc_md39 4.2. Memory Management: Reference Counting Hoshi uses an automatic reference counting (ARC) system for memory management. - Every object has a reference count, stored in its header. - When an object is created or a new reference to it is made (e.g., assignment, passing as an argument), its reference count is incremented. - When a reference goes out of scope or is reassigned, the object's reference count is decremented. - When an object's reference count reaches zero, it is deallocated. This process is handled automatically by the compiler and runtime through <tt>gc_refcount_increase</tt> and <tt>gc_refcount_decrease</tt> functions generated for each type. @subsection autotoc_md40 4.3. Object Creation - <strong>Structs:</strong> Created by calling their constructor, which is defined in an <tt>impl</tt> block. @icode{rust} let p1 = Point(1, 2); @endicode - <strong>Interfaces:</strong> An interface object is created by "casting" a struct instance that implements it. This creates a new interface object containing a pointer to the original struct instance and a virtual method table (v-table). @icode{rust} let p1 = Point(1, 2); let addable = Addable(p1); // Creates an interface object @endicode @section autotoc_md41 5. Yoi Intermediate Representation (IR) The Yoi IR is a high-level, stack-based intermediate representation. It serves as the bridge between the frontend parser and the backend code generator (LLVM). @subsection autotoc_md42 5.1. Key Components - **<tt>IRModule</tt>**: Represents a single compiled source file, containing tables for functions, structs, interfaces, globals, and string literals. - **<tt>IRFunctionDefinition</tt>**: Defines a function with its name, arguments, return type, local variable table, and code blocks. - **<tt>IRCodeBlock</tt>**: A sequence of IR instructions, analogous to a basic block. - **<tt>IRValueType</tt>**: The IR's own type system, representing Hoshi types as objects (e.g., <tt>integerObject</tt>, <tt>structObject</tt>). - **<tt>IROperand</tt>**: Arguments for IR instructions, which can be immediate values or indices into various tables. @subsection autotoc_md43 5.2. Execution Model The IR operates on a temporary value stack for each function. Instructions pop operands from this stack and push results back onto it. All values on the stack are pointers to heap-allocated, reference-counted objects. @subsection autotoc_md44 5.3. Instruction Set Highlights - <strong>Stack/Memory:</strong> <tt>push_*</tt>, <tt>load_local</tt>, <tt>store_local</tt>, <tt>load_member</tt>, <tt>store_member</tt>. - <strong>Arithmetic/Logic:</strong> <tt>add</tt>, <tt>sub</tt>, <tt>mul</tt>, <tt>div</tt>, <tt>equal</tt>, <tt>less_than</tt>, etc. - <strong>Control Flow:</strong> <tt>jump</tt>, <tt>jump_if_true</tt>, <tt>jump_if_false</tt>, <tt>ret</tt>, <tt>ret_none</tt>. - <strong>Object Lifecycle:</strong> <tt>new_struct</tt>, <tt>new_interface</tt>, <tt>construct_interface_impl</tt>. - <strong>Function Calls:</strong> <tt>invoke</tt> (static dispatch), <tt>invoke_virtual</tt> (dynamic dispatch via v-table). @section autotoc_md45 6. Compilation and Linking The Hoshi compiler (<tt>hoshi-lang</tt>) performs the following steps: 1. <strong>Parsing:</strong> The source code (<tt>.hoshi</tt>) is parsed into an Abstract Syntax Tree (AST). 2. <strong>IR Generation:</strong> The <tt>visitor</tt> traverses the AST to generate Yoi IR, contained within an <tt>IRModule</tt>. 3. <strong>IR Linking:</strong> The <tt>IRLinker</tt> combines multiple <tt>IRModule</tt>s (if there are imports) into a single, unified <tt>IRModule</tt>. It mangles names to prevent collisions. 4. <strong>LLVM Codegen:</strong> The <tt>LLVMCodegen</tt> component translates the unified Yoi IR into LLVM IR (<tt>.ll</tt> file). This phase generates the necessary LLVM structures, functions, and GC calls. 5. <strong>Object Code Generation:</strong> The LLVM IR is compiled into a native object file (<tt>.o</tt> or <tt>.obj</tt>). 6. <strong>Final Linking:</strong> An external system linker (like <tt>cc</tt> or <tt>cl.exe</tt>) is used to link the object file with the Hoshi runtime library (<tt>libelysia_runtime</tt>) to produce the final executable or library. @section autotoc_md46 7. Foreign Function Interface (FFI) Hoshi provides an FFI to interoperate with C-compatible libraries. - <strong>Importing Functions:</strong> The <tt>import</tt> keyword declares an external function, specifying its signature and the library it comes from. The compiler generates a wrapper to handle the conversion between Hoshi objects and raw C types. @icode{rust} // Imports puts from the C standard library (via a "builtin" alias) import puts(str : string) : int32 from "builtin";
  • Exporting Functions: The export keyword creates a C-compatible wrapper for a Hoshi function, allowing it to be called from other languages.
    func test(a: int, b: int) : int {
    return a + b
    }
    export test as test; // Exports a C-style function: int test(int a, int b)
  • Exporting Structs: Structs can also be exported, which generates a C-compatible layout without the Hoshi object header (i.e., no reference count).

    export Point as Point;
